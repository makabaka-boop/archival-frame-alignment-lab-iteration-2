# 胶片扫描对应 API

同卷胶片被两台扫描机分别采集。掉帧与重复画面会让首次按指纹拼接时错序。
本服务计算两台扫描机指纹数组之间的**全局最长对应**（最长公共子序列，LCS）：

- 对应关系是零基索引对 `(left_index, right_index)` 的序列；
- 两侧索引都严格递增，且两侧指纹相等；
- **先最大化对数**；对数并列时，取索引对序列（逐对比较）**字典序最小**者；
- 无任何匹配时返回空数组。

修复师可提交两类**替换语义**的约束集合并触发重算：

- **锚点集合**（已人工核实的帧对应）：结果必须包含全部锚点；
- **禁止对应对集合**（人工确认的同指纹误配）：这些对永不进入最终最长对应。

两类约束都先按相同目标（最长、字典序最小）裁决。锚点与禁止集合相交时
**整次拒绝**（`422`），约束与结果均保持调用前状态；提交空集合即清空对应
约束、恢复该维度的全局最优。

两名修复师可能同时编辑同一作业（包括两人分别改两类约束）。作业带有单调
递增的 `version`，任一成功修改都推进版本；替换请求可携带所基于的
`base_version` 与 `Idempotency-Key` 请求头：并发替换中**恰好一个**请求
成功，过期或落败的请求收到 `409` 且不改变任何状态；超时重放返回首次裁决
结果，绝不重复执行、绝不覆盖其他修复师的较新核实结论。

纯后端 API：Python 3.12 + FastAPI + PostgreSQL。无任何桩实现或假接口。

## 输入域

| 项 | 约束 |
| --- | --- |
| 数组长度 | 每侧 1..20000 项 |
| 指纹 | 1..32 个 ASCII 可打印字符（`0x20`..`0x7E`，空格至 `~`） |
| 大小写 | 按字节精确比较，区分大小写，不做任何规范化 |
| 重复 | 每个指纹值在每侧至多出现 4 次 |

不满足约束的请求返回 `422`。

## 用 Docker Compose 启动

```bash
docker compose up --build
```

服务通过环境变量 `API_PORT` 暴露（未设置时默认 `8000`）：

```bash
API_PORT=9000 docker compose up --build
# API: http://localhost:9000
```

栈包含三个服务：

- `db`：PostgreSQL 16，扫描数组、锚点、禁止对应对、结果全部落库（命名卷
  `pgdata`），容器重启后任务可继续查询与重算；
- `api`：FastAPI 应用，容器内**非 root 用户**运行；
- `verify`：pytest 验收服务，对运行中的真实 API 与真实 PostgreSQL 执行
  `tests/`，包含小规模穷举交叉核对、重复指纹、首尾锚点、受约束的较短最优解、
  清空锚点恢复全局最优、禁止对应对的穷举核对/无解/锚点相交、两类约束修改
  交错与重启后读取、最大输入 3 秒性能、落库核验，以及同步屏障交错的
  并发替换裁决、超时重放幂等验收。

查看验收结果：

```bash
docker compose up --build verify   # 或直接 docker compose up --build 后看 verify 日志
```

## HTTP 协议

### `POST /api/jobs` — 创建任务并计算全局最长对应

请求体：

```json
{ "left": ["A", "a", "b"], "right": ["a", "b", "A"] }
```

`201` 响应：

```json
{
  "id": "7e3..uuid",
  "left": ["A", "a", "b"],
  "right": ["a", "b", "A"],
  "anchors": [],
  "forbidden_pairs": [],
  "result": [
    { "left_index": 0, "right_index": 2 },
    { "left_index": 2, "right_index": 1 }
  ],
  "length": 2,
  "version": 0,
  "updated_at": "2026-09-23T12:00:00.000000+00:00"
}
```

> `A(0)→A(2)` 与 `a(1)→a(0)` 交叉不能同取；两条长度 2 的最优解中，
> 首对字典序更小的 `(0,2)` 胜出。

### `GET /api/jobs/{id}` — 查询任务（含当前锚点、禁止对应对与结果）

不存在返回 `404`。响应始终包含当前 `version` 与 `updated_at`（UTC），
供后续替换请求携带 `base_version`；`anchors` 与 `forbidden_pairs` 均为
规范化（去重、按两侧索引升序）后的集合。

### `PUT /api/jobs/{id}/anchors` — 用新锚点集合替换旧集合并重算

请求体（空数组 = 清空锚点；`base_version` 可选）：

```json
{ "anchors": [[2, 1], [4, 3]], "base_version": 2 }
```

返回与 `GET` 相同的完整任务表示（含新 `version` 与 `updated_at`），其中
`anchors` 为规范化（按两侧索引升序）后的集合，`result` 包含全部锚点；
当前禁止对应对集合原样保留并继续生效。

锚点合法条件（与结果条件一致）：

1. 每个锚点是 `[left_index, right_index]` 整数对，索引在各自数组范围内；
2. 该位置两侧指纹相等；
3. 全部锚点在左索引、右索引上都严格递增（不得共用索引或交叉）。

任一不满足，或锚点与当前禁止集合相交，返回 `422`
（响应体 `{"detail": "原因"}`），**锚点、禁止集合与结果均保持调用前状态**。
锚点可以排除掉全局最优解，使含锚点的最优比对数更短。

### `PUT /api/jobs/{id}/forbidden-pairs` — 替换禁止对应对集合并重算

胶片修复师确认两台扫描机的少数同指纹画面并非同一帧：这些误配点通过本入口
登记为“禁止对应对”，重算时不得进入最终最长对应。

请求体（空数组 = 清空禁止集合；`base_version` 可选）：

```json
{ "forbidden_pairs": [[2, 1], [4, 3]], "base_version": 2 }
```

返回与 `GET` 相同的完整任务表示；`forbidden_pairs` 为规范化（去重、按两侧
索引升序）后的集合，`result` 是避开全部禁止对后的最长对应；当前锚点集合
原样保留并继续被结果包含。

禁止对应对合法条件：

1. 每对是 `[left_index, right_index]` 整数对，索引在各自数组范围内；
2. 该位置两侧指纹相等（只登记“同指纹误配”，指纹本就不等的对不可能入选）。

禁止对之间**不要求**有序：允许交叉、允许共用左/右索引、允许重复（去重）。
当新禁止集合与当前锚点集合相交时，整次请求返回 `422` 且不留任何修改——
人工核实的锚点永远不会被静默排除。禁止集合可以把所有相等对全部排除，此时
结果为空数组（无解）。

### 并发裁决与幂等

- `version` 创建时为 `0`，每次**成功**修改（锚点或禁止集合，任一入口）加一；
  `updated_at` 记录最近一次成功修改（创建或替换）的 UTC 时间。任何
  `404/422/409` 都不改变锚点、禁止集合、结果、`version` 或 `updated_at`。
- `base_version` 表示本次编辑所基于的作业版本（通常取自最近一次 `GET`）。
  与当前版本不一致时返回 `409`（`{"detail": "原因"}`）并拒绝执行；
  缺省时不做该检查，顺序调用的旧客户端行为不变。
- 即使请求读到的版本与 `base_version` 一致，落库仍通过
  `UPDATE ... WHERE version = <读取版本>` 做原子裁决：两名修复师基于同一
  旧状态并发替换时（即使两人改的是不同类约束），数据库行锁串行化提交，
  **恰好一个**请求成功，另一个返回 `409`，先前已确认的约束与重算结果不会
  被静默覆盖。
- `Idempotency-Key` 请求头标识同一逻辑请求（锚点请求与禁止请求属不同逻辑
  操作）。首次成功响应与状态变更在同一事务内持久化；超时或断线后用
  **同一键、同一请求体**重放，直接返回首次裁决结果，不重复执行、不推进
  版本。若首次应用后状态已被其他请求（含另一类约束的修改）推进，重放返回
  `409` 并说明已应用的版本；同一键搭配不同请求体同样返回 `409`。
- 约束（锚点、禁止对应对）、结果与版本在同一事务、同一行原子落库，失败不
  留半次修改；成功响应与随后读取到的持久状态逐项一致，重复 `GET` 结果相同。
- 升级前创建的旧作业没有禁止集合列，读取时按**空禁止集合**处理；迁移为
  幂等就地加列，不影响既有锚点、结果与版本。

### `GET /health`

返回 `{"status":"ok"}`。

## 算法

普通的 O(n·m) 动态规划无法处理 20000×20000。本实现把问题归约为二维点列上的
最长链（LIS）：

1. 收集所有指纹相等的索引对（因每个指纹每侧至多 4 次，总数 K ≤ 80000），
   命中禁止对应对的点直接剔除；
2. 用 Fenwick 树按左索引分组、在右索引上维护后缀最大值求每点链长，
   整体 O(K log K)；
3. 重建阶段按链长分桶，每步取“晚于当前游标”的字典序首个点，得到
   最长解中唯一的字典序最小序列；
4. 锚点沿两条轴把索引平面切成互不相交的矩形段，逐段独立求解（同样跳过
   禁止对）后以锚点连接。

接口、算法与存储层共享同一份规范化索引身份（`app/pairs.py`）：
`(left_index, right_index)` 整数二元组，集合统一去重并按两侧索引升序。

最大规模实测远低于 3 秒预算。

## 本地开发（无 Docker）

```bash
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
export DATABASE_URL=postgresql+psycopg://lcs:lcs@localhost:5432/lcs
uvicorn app.main:app --port 8000
pip install -r requirements-test.txt
API_BASE_URL=http://localhost:8000 PG_DSN=postgresql://lcs:lcs@localhost:5432/lcs pytest -v
```

`scripts/brute.py` 是 O(n²) 穷举参考实现，仅供验收交叉核对，不参与服务运行。
